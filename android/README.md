# MELAOS STUDIOS — Android app (Trusted Web Activity)

The Android app is a Trusted Web Activity: a thin wrapper, generated by
[Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap), that opens
https://melaosstudios.com full screen in Chrome. There is no native app code; the
website is the app.

- Package: `com.melaosstudios.app`
- Project: `android/twa/` (`twa-manifest.json` is the source of truth; everything
  else in that folder is generated from it)
- Store graphics and listing drafts: `android/store-listing/`
- Digital Asset Links: `apps/web/public/.well-known/assetlinks.json`. It must be
  live at https://melaosstudios.com/.well-known/assetlinks.json, or the app shows
  a browser address bar. It lists two SHA-256 fingerprints: Google Play's app
  signing key and the upload key.

## Releasing a new version

1. In `twa-manifest.json`, raise `appVersionCode` (2 → 3 …) and `appVersionName`.
   Play rejects a version code it has seen before, including ones in drafts.
2. Regenerate and build (unsigned), from `android/twa`:
   ```
   bubblewrap update --skipVersionUpgrade
   bubblewrap build --skipSigning
   ```
   Bubblewrap fetches the icons from `iconUrl` / `maskableIconUrl`, so deploy the
   site first if the icons changed.
3. Sign `app/build/outputs/bundle/release/app-release.aab` into
   `app-release-bundle.aab` with the upload key, e.g.
   `jarsigner -sigalg SHA256withRSA -digestalg SHA-256 -keystore <keystore> -signedjar app-release-bundle.aab app/build/outputs/bundle/release/app-release.aab melaos`
   (on this PC, double-click `Create key and sign MELAOS app.bat` in the key folder).
4. Upload `app-release-bundle.aab` in Play Console.

Notes from the first build (November 2026):
- `minSdkVersion` is 24: androidbrowserhelper 2.7.x requires Android 7.0, while
  Bubblewrap still defaults to 21.
- Bubblewrap 1.27 targets SDK 36 and needs build-tools 36.1.0.
- Bubblewrap checks for JDK 17 only in `doctor`/setup; the build itself ran fine on JDK 21.
